# Frozen benchmark

`python tools/benchmark.py smoke` reuses the installed Python API and real Go binaries, performs a warm DAG and one measured-for-instrumentation DAG on two workers, checks the exact arithmetic result and retains confirmed owned cleanup. This is a correctness smoke, not a performance result. `python -m unittest discover -s tools -p test_benchmark.py -v` checks axis coverage and timeout accounting.

`python tools/benchmark.py benchmark` requires isolated Linux execution. Version 1 uses seed 421 and a nine-cell one-axis-at-a-time design around two workers, 4096 object items, 20ms task delay and concurrency eight. Axes cover workers 1/2/4, object items 16/4096/32768, delay 0/20/200ms and concurrency 1/8/32. Five repetitions reverse cell order on alternating repeats. Each cell owns fresh state and starts with an untimed warm DAG, followed by 32 DAGs through trusted `slow` and `total`. One-worker cells are a matched worker baseline; other axes compare their same-base neighbor. This avoids an unrequested Cartesian explosion while covering each frozen axis. Fixed-rate 1/4/16 DAG/s sweeps run for ten seconds, then the highest zero-loss rate with dispatch-p99 <100ms and end-to-end-p99 <5s runs for 120s. Queues beyond concurrency32 are explicit generator declines. Separate one-DAG worker-loss and coordinator-restart journeys observe assigned work before injection and require a higher accepted attempt plus the exact result.

Raw `.runs/benchmark-*/` receipts retain source/dirty state, environment, workload, input hashes, intended arrival/start/result timestamps, outcomes, exact task IDs and state, peer transfers and Linux /proc CPU/RSS for tracked processes and generator at 100ms. Client retries and 50ms result polling are included in latency. CPU ticks require the retained clock-tick conversion. Windows smoke resource fields are null. Original hosted resources omitted Python children. Profile-only descendant snapshots now inspect all native OS threads, validate parent identity and retain start-time/reaped-child CPU ticks separately. Short-lived RSS can still escape sampling; overlapping live/reaped counters must not be blindly summed.

`profile` now selects a separate benchmark-tag binary and the exact failed 16 DAG/s, ten-second cell: two workers, 4,096 items, 20 ms task delay and concurrency 32, with all 160 outcomes retained. It requests standard native CPU profiles from the coordinator and both workers after warmup, captures them before cleanup, and keeps generator cProfile/Go scheduler traces separately. Nonempty bounded profiles are required; diagnostic timings are excluded from comparisons. The normal binary's helper is a no-op; benchmark-only listeners synchronously validate numeric loopback addresses and serve only bounded CPU profiles. This preparation awaits main source review and hosted native checks/profile evidence. See [exact commands, artifact allowlist and future native k6 plan](../../../../docs/benchmarks/native-profile-plan.md). No product optimization is justified yet; the initial published baseline remains unchanged.
